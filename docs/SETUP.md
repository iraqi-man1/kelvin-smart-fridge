# Kelvin — Smart Fridge Monitor

داشبورد بثلاث لغات (العربية، English، Bahasa Melayu) لمشروع الثلاجة الذكية: **ESP32-WROOM-32 DevKit + DHT11 + CCS811**.

**تصميم الطالب:** ALSARRAY ALI AHMED ALI — مشروع طلابي، Universiti Sains Malaysia.

## التشغيل

يتطلب Node.js 20.19+ أو 22.12+.

```powershell
npm install
npm run dev
```

افتح http://localhost:5173. يبدأ المشروع ببيانات تجريبية، ولا يحتاج جهازاً لتجربة الواجهة. اللغة تتغير من أسفل القائمة الجانبية (ع / EN / BM) وتُحفظ في المتصفح، ورسائل تلكرام تتبع اللغة نفسها.

```powershell
npm run build
npm start
npm test
```

لاختبارات المتصفح: شغّل `npx playwright install chromium` مرة واحدة، ثم `npm run test:e2e`.

## قاعدة البيانات (Supabase)

Kelvin يحفظ بياناته بقاعدة بيانات PostgreSQL على **Supabase**: الحسابات والجلسات والصور الشخصية وإعدادات تلكرام، و**كل** القراءات (مو بس آخر 2,000). بدون إعداد يبقى يشتغل على ملفات JSON بمجلد `data/` مثل قبل.

**الربط (مرة وحدة):**

1. سوِّ مشروع بـ [supabase.com](https://supabase.com) (المجاني يكفي) واحفظ كلمة سر قاعدة البيانات.
2. من المشروع اضغط **Connect** ← **Session pooler** وانسخ الرابط (URI). بدّل `[YOUR-PASSWORD]` بكلمة سر قاعدة البيانات.
3. انسخ `.env.example` باسم `.env` وحط الرابط بعد `DATABASE_URL=`.
4. شغّل `npm run dev`. أول مرة يسوي الخادم الجداول وحده، وينقل بياناتك من ملفات JSON مرة وحدة، ويطبع:
   ```
   [database] copied the JSON data into PostgreSQL: {...}
   [database] Supabase (PostgreSQL)
   ```
   ولوحة **الجهاز** تبيّن «قاعدة البيانات: Supabase (PostgreSQL)».

**الجداول** (كلها تبدأ بـ `kelvin_`، والمخطط كامل بـ `supabase/schema.sql`): `kelvin_users`، `kelvin_sessions`، `kelvin_avatars` (الصور بصيغة bytea)، `kelvin_readings` (فهرس على الوقت)، `kelvin_settings`.

**الأمان:**
- Row Level Security مفعّل على كل الجداول بدون سياسات، فمفتاح Supabase العام (anon) ما يگدر يقرأها. بس الخادم، المتصل كمالك قاعدة البيانات، يوصلها.
- كلمات السر ورمز القفل مخزّنة مشفّرة (scrypt)، مو كنص.
- لا تشارك ملف `.env` (موجود بـ `.gitignore`). الاتصال مشفّر (TLS)؛ حتى يتأكد الخادم من شهادة Supabase نفسها، نزّلها من Project Settings ← Database ← SSL وحط مسارها بـ `DATABASE_CA`.

**ملاحظات:**
- إذا ما گدر يتصل، الخادم يوقف ويطبع السبب (حتى ما تنقسم البيانات بين مكانين).
- بعد الربط، ملفات `data/*.json` تبقى نسخة احتياطية قديمة وما تتحدث.
- كل قراءة نحو 100 بايت؛ قراءة كل ساعة ونص = 16 قراءة باليوم ≈ 1.6 KB باليوم. المجاني بـ Supabase 500 MB يكفي سنين.
- الاختبارات (`npm test`) تشغّل نفس الكود على PostgreSQL 16 حقيقي محلياً (PGlite)، بدون إنترنت.

## الحساب والملف الشخصي

أول مرة تفتح اللوحة تظهر صفحة **تسجيل الدخول**؛ اضغط «إنشاء حساب» وسجّل باسمك وبريدك وكلمة سر (8 أحرف على الأقل). كل شخص له حسابه.

- **حسابي** (من بطاقتك أسفل القائمة، أو صورتك أعلى الشاشة في الموبايل): صورة شخصية تُقص مربعة 256 px، الاسم، الرقم الجامعي، الجامعة، الكلية، الهاتف، ونبذة، مع نسبة اكتمال الملف.
- تغيير كلمة السر (يسجّل خروجك من أجهزتك الأخرى)، تسجيل الخروج، وحذف الحساب بتأكيد كلمة السر.
- كلمات السر مخزّنة بـ scrypt مع salt، والجلسة كوكي `HttpOnly` لمدة 30 يوماً. بعد 10 محاولات دخول فاشلة من نفس الجهاز ينتظر 15 دقيقة.
- كل واجهات اللوحة تحتاج تسجيل دخول، **ما عدا** `POST /api/readings` حتى يبقى ESP32 يرسل بدون حساب.
- الحسابات والجلسات والصور في `data/users.json` و`data/sessions.json` و`data/avatars/`.
- **الصورة الشخصية:** بعد اختيار الصورة تفتح نافذة ضبط: تكبير (الشريط أو عجلة الماوس)، سحب لتحريكها داخل الدائرة، تدوير 90°، وإعادة ضبط. تُحفظ مربعة 512 px.

### الصلاحيات والدعوات

| الصلاحية | تقدر |
|---|---|
| **مدير** | كل شيء: المستخدمون والدعوات، تلكرام، مفاتيح الجهاز، التحكم |
| **مشغّل** | اللوحة كاملة وإرسال أوامر للجهاز |
| **مشاهد** | المشاهدة فقط |

- أول حساب يصبح مديراً (والحسابات القديمة: الأقدم صار مديراً).
- الحسابات الجديدة **بالدعوة فقط** (التسجيل الذاتي متاح لأول حساب فقط): من صفحة **المستخدمون** يكتب المدير اسم الشخص وبريده وصلاحيته و**كلمة سره**، فيصله رابط على بريده. يفتح الرابط ويكتب كلمة السر التي أعطاه إياها المدير، فيُنشأ حسابه ويدخل مباشرة (ويقدر يغيّرها لاحقاً من حسابه). كلمة السر لا تُرسل بالبريد أبداً، والرابط يُستخدم مرة واحدة ويبقى 7 أيام، وكلاهما يُخزَّن مشفّراً. الدعوة تحتاج إعداد البريد (Gmail).
- **كلمات سر الأعضاء:** في جدول الحسابات يرى المدير كلمة السر التي حددها هو (بالدعوة أو بزر **تغيير**)، ويقدر يغيّرها بأي وقت؛ التغيير يُخرج العضو من حسابه ليدخل بالجديدة. تُحفظ مشفّرة (AES-256-GCM، المفتاح من `VAULT_KEY` أو من عنوان قاعدة البيانات). إذا غيّر العضو كلمة سره بنفسه، تظهر «اختارها بنفسه» ولا تُحفظ إلا مُجزّأة (hash) كالعادة.
- إذا ما وصلت الدعوة للبريد: بعد الإرسال يظهر زر **نسخ الرابط**، وفي الدعوات بالانتظار زر **إعادة الإرسال** (رابط جديد ويبطل القديم).
- الصلاحيات تُطبّق على الخادم نفسه (403)، مو بس بإخفاء الأزرار. لازم يبقى مدير واحد على الأقل.

### مفتاح الجهاز

من **ربط الجهاز ← البرنامج** ينشئ المدير **مفتاح جهاز** يظهر مرة واحدة ويدخل مباشرة في برنامج Arduino (الهيدر `X-Device-Key`). بمجرد وجود مفتاح، أي قراءة بدونه أو بمفتاح خاطئ تُرفض (401). المفاتيح مخزّنة مشفّرة ويمكن حذفها.

**استبدال المفتاح:** إذا انكشف المفتاح، اضغط **استبدال** بجانبه: ينعمل مفتاح جديد يدخل بالبرنامج، والقديم يبقى شغّال لحد ما الجهاز يرسل أول قراءة بالجديد، أو 24 ساعة كحد أقصى، حتى ما تنقطع القراءات وانت ترفع الكود.

### التحكم بالجهاز من الموقع

لوحة **التحكم بالجهاز** في «نظرة عامة» (للمدير والمشغّل): صفير (1–3)، LED (تشغيل/وميض/إطفاء)، رسالة على شاشة OLED (حتى 40 حرفاً إنكليزياً)، وإعادة تشغيل. سرعة القراءات **ثابتة** (قراءة كل ساعة ونص) وما تنغير من هنا. الأمر يصل مع **الرد على القراءة التالية**، والجهاز يؤكد تنفيذه في القراءة بعدها (بالانتظار ← أُرسل ← نُفّذ). كل أمر يُرسل مرة واحدة فقط حتى لا تتكرر إعادة التشغيل.

البرنامج الجديد يحتاج المكتبات: DHT sensor library، Adafruit CCS811، Adafruit SSD1306 (+GFX)، ArduinoJson. التوصيل: OLED و CCS811 على I²C (SDA → GPIO 33، SCL → GPIO 32، عنوان الشاشة 0x3C)، LED على GPIO 26 مع 220 Ω، البزر على GPIO 25. إذا DHT11 ما جاوب على GPIO 27، البرنامج يدوّر عليه بالأطراف الثانية عند التشغيل ويكتب بالـ Serial Monitor وين لگاه.

### صفحة «كيف يعمل النظام»

مخطط حيّ: الحساسات ← ESP32 ← الخادم ← Supabase، ومن الخادم إلى اللوحة وتلكرام والبريد، وخط الأوامر الراجع للجهاز. كل جزء يعرض حالته الآن (آخر قراءة، مفتاح الجهاز، عدد القراءات المحفوظة، تلكرام والبريد)، مع رحلة القراءة خطوة بخطوة وطرق الحماية. مفيدة للعرض أمام اللجنة.

### نسيت كلمة السر

كلمات السر مخزّنة مشفّرة (scrypt)، فلا أحد يقدر يرجّع القديمة، ولا حتى الخادم. بدلها تُعيَّن كلمة جديدة:

1. في صفحة الدخول اضغط **«نسيت كلمة السر؟»** واكتب بريد الحساب.
2. يصل رمز من 6 أرقام (نفس قواعد الرمز: 10 دقائق، 5 محاولات، إعادة إرسال كل دقيقة).
3. اكتب الرمز وكلمة السر الجديدة مرتين ← تدخل مباشرة، وكل جلساتك الأخرى تنتهي.

الرد واحد سواء كان للبريد حساب أم لا، حتى لا تُستعمل الصفحة لمعرفة من عنده حساب. تحتاج إعداد البريد (Gmail) أدناه.

### الإعدادات محفوظة بالحساب على الخادم

إعدادات اللوحة (اسم الجهاز، الحدود، القطع، الجهد، السعر، العملة، الطمس)، وإعدادات القفل، واللغة، والمظهر، ومصدر البيانات تُحفظ مع حسابك في Supabase (عمود `prefs` في `kelvin_users`)، فتلحقك على أي جهاز أو متصفح. أول دخول ينقل إعدادات المتصفح القديمة إلى الحساب ويحذفها منه. المتصفح يحتفظ فقط بنسخة مؤقتة من اللغة والمظهر حتى تظهر صفحة الدخول بهما.

### التحقق بخطوتين (رمز بالبريد)

من **حسابي ← التحقق بخطوتين** تفعّله بعد ما يوصلك رمز تجريبي على بريدك. بعدها كل تسجيل دخول بكلمة السر يطلب **رمزاً من 6 أرقام** يُرسل إلى بريد الحساب.

- الرمز يعمل مرة واحدة وينتهي خلال 10 دقائق، و5 محاولات خاطئة تلغيه، و«إرسال رمز جديد» مرة كل دقيقة (5 مرات كحد أقصى).
- الرمز لا يُخزّن كما هو، بل بصمته (SHA-256) فقط. الرسالة بلغة الواجهة (عربي، إنكليزي، ماليزي).
- الإيقاف يحتاج كلمة سر الحساب.

**إعداد الإرسال (Gmail):**
1. في حساب Google: **الأمان ← التحقق بخطوتين** (لازم يكون مفعّلاً)، ثم **كلمات مرور التطبيقات** ← أنشئ واحدة باسم Kelvin. تعطيك Google 16 حرفاً.
2. شغّل:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\set-gmail.ps1
   ```
   يسأل عن عنوان Gmail، ثم كلمة مرور التطبيقات مخفية، ويحفظهما في `.env`.
3. أعد تشغيل الخادم؛ يطبع `[email] sending is set up`.

بدون إعداد الإرسال يبقى خيار التحقق بخطوتين مقفلاً حتى لا ينغلق حسابك. ⚠️ إذا فعّلته ثم حذفت إعداد البريد من `.env` فلن تستطيع الدخول حتى ترجعه.

### قفل الشاشة (مثل ويندوز)

- **Ctrl + Shift + L** أو «قفل الشاشة» في القائمة يقفل اللوحة فوراً: شاشة بالساعة والتاريخ، وأي زر أو نقرة تُظهر صورتك واسمك وخانة كلمة السر.
- **Win + L** لا يصل لأي صفحة ويب لأن ويندوز يلتقطه قبل المتصفح. لكن عندما يقفل ويندوز تنخفي نافذة المتصفح، فيقفل Kelvin نفسه بعد 10 ثوانٍ من الإخفاء (قابل للتغيير: فوراً، 10 ث، دقيقة، أبداً)، ويطلب كلمة السر عند رجوعك.
- قفل عند عدم النشاط (1، 5، 15، 30 دقيقة) اختياري من «حسابي ← قفل الشاشة».
- القفل محفوظ على الخادم أيضاً: أثناء القفل ترجع واجهات اللوحة `423`، وتحديث الصفحة لا يتجاوزه. ESP32 يبقى يرسل القراءات عادي.

## الحساسات والتوصيل

| الحساس | يقيس | التوصيل بـ ESP32 |
|---|---|---|
| **DHT11** (وحدة مع LED ومقاومة) | الحرارة °C والرطوبة % | `+` → 3V3، `S/OUT` → GPIO 27، `−` → GND |
| **CCS811** (CJMCU-811) | eCO2 بالـ ppm و TVOC بالـ ppb | VCC → 3V3، GND → GND، SDA → GPIO 33، SCL → GPIO 32، **WAK → GND**، ADD → GND |

- DHT11: دقة ±2 °C و ±5 %RH، مرة كل ثانية كحد أقصى.
- CCS811: عنوان I²C هو `0x5A`. يحتاج 20 دقيقة بعد كل تشغيل، ونحو 48 ساعة أول مرة، قبل الاعتماد على قيمه. eCO2 تقدير من المركبات العضوية، وليس قياساً حقيقياً لثاني أكسيد الكربون.

## ربط الجهاز خطوة بخطوة

افتح **ربط الجهاز** من القائمة واتبع الخطوات الست: القطع المطلوبة، التوصيل، تجهيز Arduino IDE والمكتبات (`esp32` من Espressif، `DHT sensor library` و`Adafruit CCS811 Library` من Adafruit)، ثم البرنامج جاهزاً للنسخ بعد كتابة اسم شبكة Wi-Fi وكلمة سرّها (لا تُحفظ ولا تُرسل)، ثم الرفع وحل المشاكل الشائعة، وأخيراً صفحة تتأكد من وصول أول قراءة.

## تنزيل القراءات على Excel

زر **تنزيل Excel** يحفظ ملف `.xlsx` فيه ورقتان: **القراءات** (التاريخ، الوقت، كل قياس بعمود ووحدته، الحالة، الجهاز؛ القيم المتجاوزة للحد بالأحمر، وصف العناوين ثابت وعليه فلتر)، و**الملخص** (الجهاز، الفترة، عدد القراءات، والأدنى والمتوسط والأعلى لكل قياس). عناوين الملف بلغة الواجهة. في صفحة السجل ينزّل نتائج البحث فقط.

## نص رسائل تلكرام

من **تنبيهات تلكرام ← نص الرسالة** تكتب رسالة التنبيه ورسالة الرجوع للمعدل الطبيعي كما تريد. الوسوم `{sensor}` `{state}` `{value}` `{limit}` `{device}` `{time}` تُستبدل بالقيم الحقيقية عند الإرسال، والمعاينة تظهر تحت كل خانة. زر «إرسال رسالة تجريبية» يرسل مثالاً بنصّك. إذا تركت النص الافتراضي فهو يتبع لغة الواجهة.

## إرسال القراءات من الجهاز

```http
POST http://COMPUTER_LAN_IP:5173/api/readings
Content-Type: application/json

{ "temperature": 26, "humidity": 58, "eco2": 612, "tvoc": 37, "deviceId": "ESP32-WROOM-32", "rssi": -54, "uptime": 3600 }
```

`temperature` و`humidity` و`eco2` و`tvoc` مطلوبة. `rssi` و`uptime` اختياريان؛ أرسل `uptime` بالثواني ليظهر استهلاك الطاقة منذ آخر تشغيل. يُسجّل وقت الاستقبال على الخادم. الخادم مناسب للشبكة المحلية الموثوقة ولا يحتوي حسابات أو مصادقة للنشر العام.

## استهلاك الطاقة (بدون حساس)

صفحة **الطاقة** تقدّر استهلاك النظام كله بدون حساس طاقة: القدرة الآن، والطاقة اليوم ومنذ آخر تشغيل، وتكلفة شهر تشغيل، واستهلاك كل قطعة، والطاقة لكل ساعة خلال آخر 24 ساعة.

**طريقة الحساب:** `E = V × I × t`. التيار لكل قطعة من ورقتها الفنية (القائمة ومصادرها في `src/power.ts`)، والزمن من قراءات الجهاز نفسها:

- قطع تسحب **دائماً** (ESP32، اللوحة، الشاشة…) تُحسب طوال الوقت الذي كان الجهاز يرسل فيه. فجوة أطول من 10 دقائق بين قراءتين تُعدّ إطفاءً.
- قطع تسحب **لكل قراءة** (إرسال Wi-Fi، قياس SHT31، سخّان BME680) تُحسب بعدد القراءات المرسلة.
- قطع تعمل **وقت التنبيه** (LED والبزر) تُحسب بالوقت الذي كانت فيه القراءة فوق الحد.

القطع التي تعمل على 3.3 V تمر عبر منظّم اللوحة الخطّي، فتسحب التيار نفسه من مدخل 5 V. اختر القطع الموصولة فعلاً، وجهد التغذية، وسعر الكيلوواط ساعة (الافتراضي `0.27 RM`) من **الإعدادات**. أرسل `uptime` من الجهاز ليظهر استهلاك الطاقة منذ آخر تشغيل.

الرقم تقدير وليس قياساً؛ قد يختلف عن الاستهلاك الفعلي بنحو 30%.

## النشر على Netlify

الموقع: https://kelvin-smart-fridge.netlify.app — الصفحات من `dist/`، والـ API كله دالة واحدة (`netlify/functions/api.mjs`) تشغّل نفس كود `server/app.mjs`. كل الحالة (الجلسات، رموز البريد، محاولات الدخول، أوامر الجهاز، حالة تنبيهات تلكرام) محفوظة في Supabase لأن نسخ الدالة قصيرة العمر ومتعددة.

المتغيرات (تُضاف مرة واحدة، من جهازك):

```
npx netlify login
npx netlify link --id 8a77b07c-921c-4cb8-978f-686097e34e12
npx netlify env:import .env
```

ثم أعد النشر حتى تقرأها الدالة. `DATABASE_URL` ضروري (منفذ 5432 يتحول تلقائياً إلى 6543، الـ transaction pooler)؛ `GMAIL_USER` و`GMAIL_APP_PASSWORD` للرموز بالبريد؛ `TELEGRAM_*` لتلكرام.

الجهاز: في «ربط الجهاز» صار العنوان `https://…/api/readings`، والبرنامج المولَّد يستخدم `WiFiClientSecure` ويتصل بالسيرفر كل 30 ثانية حتى يستلم الأوامر، بس السيرفر **يحفظ قراءة وحدة كل ساعة ونص** بأوقات ثابتة (00:00، 01:30، 03:00 … حسب `KELVIN_TIMEZONE`). أول اتصال بكل فترة هو اللي ينحفظ، والباقي يرجعله الرد 200 ويه الأوامر بدون ما ينحفظ. ما أحد يكدر يغير هذا الجدول، لا من الموقع ولا من كود الجهاز. (الخطة المجانية لها حد لعدد الطلبات — راقب **Usage** في Netlify.)

## الدعم الفني والأوسمة

- **الدعم الفني** (بالقائمة): أي مستخدم يكتب عطلاً أو مشكلة (عطل، مشكلة، حساب، سؤال) فتوصل لبوت تلكرام **خاص بقسم تقنية المعلومات** — غير بوت تنبيهات الثلاجة — مع اسمه وبريده وصلاحيته ورقم البلاغ. المدير يربط البوت من نفس الصفحة (التوكن من @BotFather و Chat ID لكروب القسم)، أو بالمتغيرين `IT_BOT_TOKEN` و `IT_CHAT_ID`. التوكن لا يرجع للمتصفح أبداً. حتى 5 بلاغات بالساعة لكل شخص؛ كل واحد يشوف بلاغاته والمدير يشوف الكل.
- **الأوسمة** (في «حسابي»): 13 وسام (أول خطوة، أيام الاستخدام، السلاسل المتتالية، شهر كعضو، التحقق بخطوتين، قفل الشاشة، الصورة، تصدير Excel، أمر للجهاز، بلاغ للدعم) مع أرقام الاستخدام. تُحسب على الخادم (الإعداد `activity`) فما يمكن منحها من المتصفح.
- الإعدادات وتلكرام وربط الجهاز والدليل صارت **صفحات** بدل نوافذ منبثقة، والقائمة الجانبية تنزل (scroll) على الشاشات القصيرة.

## إشعارات ntfy

صفحة **قنوات التنبيه** (الإدارة ← قنوات التنبيه) فيها تلكرام و **ntfy** جنب بعض؛ كل تنبيه حساس يروح لكل قناة مفعّلة، وإذا وحدة فشلت الثانية توصل.
1. فعّل «إرسال التنبيهات إلى ntfy أيضاً» — يتولّد موضوع (Topic) عشوائي طويل تلقائياً — واضغط حفظ.
2. نزّل تطبيق **ntfy** (Android / iOS) أو افتح ntfy.sh، اضغط + واشترك بنفس الموضوع.
3. اضغط «تجربة ntfy».

الأولوية: عادية / عالية / طارئة (الطارئة ترن حتى بالوضع الصامت). تنبيه الرجوع للطبيعي يوصل بأولوية عادية. على ntfy.sh أي واحد يعرف اسم الموضوع يكدر يقراه، فلا تشاركه؛ لخادم ntfy خاص يمكن إضافة رمز وصول (لا يرجع للمتصفح). بديل للإعداد من الصفحة: المتغيرات `NTFY_TOPIC`، `NTFY_TOKEN`، `NTFY_SERVER`.

## التوقعات وملف Excel

- **التوقع بالرسم البياني:** خيار «التوقع» فوق «القراءات عبر الزمن». لكل حساس خط متقطع ومنطقة مظللة بعد «الآن» (15 دقيقة لفترة ساعة، ساعة لـ 6 ساعات، 3 ساعات لـ 24 ساعة)، ومعه القيمة المتوقعة ومداها (95%)، والاتجاه بالساعة، وتحذير «ممكن يتجاوز الحد خلال ~X دقيقة». الطريقة: خط اتجاه بالمربعات الصغرى على القراءات الأخيرة، والاتجاه اللي ما يختلف عن الضجيج يُعتبر ثابت. تقدير قصير المدى، مو ضمان.
- **Excel:** أربع أوراق: القراءات، الملخص، **الطاقة** (لكل قطعة: التيار والشحنة والطاقة ونسبتها، والمجموع والكلفة والتقدير الشهري — كلها معادلات تتحدث إذا غيّرت الجهد أو السعر — والطاقة لكل ساعة)، و**الرسوم البيانية** (رسم لكل حساس مع الحد والتوقع، ورسمين للطاقة). الرسوم صور داخل الملف لأن مكتبة Excel المستخدمة ما تدعم الرسوم الأصلية.

## الأمان

- **حد محاولات الدخول:** 5 كلمات سر غلط على نفس الحساب (من أي مكان) توقف الدخول له 15 دقيقة، و10 محاولات من نفس عنوان IP توقفه هو. صاحب الحساب يوصله إيميل أول ما يتوقف.
- **دخول من جهاز جديد:** كل متصفح ياخذ رقم عشوائي بكوكي HttpOnly (ينحفظ منه hash بس). إذا دخل الحساب من متصفح ما استخدمه قبل، يوصل لصاحبه إيميل بالوقت والمتصفح وعنوان IP. أول دخول للحساب ما يرسل شي.
- **سجل الأمان** (الإدارة ← سجل الأمان، للمدير فقط): تسجيلات الدخول والمحاولات الفاشلة والمحظورة، الأجهزة الجديدة، الدعوات، تغيير الصلاحيات، حذف المستخدمين، مشاهدة أو تغيير كلمة سر عضو، مفاتيح الجهاز وأوامره، وتغيير قنوات التنبيه والإعدادات. ينحفظ آخر 400 سجل، وما ينكتب بيه أي كلمة سر أو رمز أو مفتاح.
- **مفتاح الخزنة `VAULT_KEY`:** كلمات السر اللي يحددها المدير للأعضاء تتشفّر بيه. بدونه يُستخدم رابط قاعدة البيانات، وصفحة سجل الأمان تنبّهك. سوّي قيمة عشوائية طويلة:

  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
  ```

  وحطها بنفسك في Netlify (Site configuration ← Environment variables ← `VAULT_KEY`) وأعد الرفع. كلمات السر القديمة تنتقل للمفتاح الجديد وحدها.
- **رؤوس الحماية** (بملف `netlify.toml`): ‏Content-Security-Policy (السكربتات من الموقع نفسه بس، ومنع عرض الموقع داخل iframe)، HSTS، ‏nosniff، ‏Referrer-Policy، و Permissions-Policy.
- **المكتبات:** `npm audit --omit=dev` يطلع 0 ثغرات (nodemailer 10، و uuid 11 عن طريق `overrides`).

## مقارنة الفترات

فوق الرسم البياني اختار **مقارنة**: الفترة السابقة، أمس (للساعة و 6 ساعات)، أو الأسبوع الماضي. الفترة القديمة تنرسم خط منقّط بنفس اللون، وفوق كل حساس يطلع المعدل الآن ومعدل الفترة القديمة والفرق (بالقيمة والنسبة). لما تأشر بالماوس يطلع قيمة الفترة القديمة بنفس الوقت والفرق بينهم. القراءات القديمة تجي من `/api/readings/range` كمعدلات (300 نقطة كحد أقصى) حتى تبقى خفيفة حتى لأسبوع كامل.
